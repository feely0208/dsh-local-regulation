# 适用范围：先确认运营地，再看报告

> **本插件只覆盖上海、深圳两市条例；是否适用取决于实际运营地，需人工确认。**

## 为什么把这件事放在最前面

地方性法规的适用范围由**实际运营地 / 业务发生地**决定，而不是由代码仓库决定。
同样一份代码，部署在上海的门店和部署在成都的门店，适用的地方规则可能完全不同。
静态扫描器无法、也不应该替你判断运营地：猜错了，要么用错规则吓人，要么漏掉真正适用的要求。

所以本插件的定位是：**你已经确认适用上海或深圳之后，用来自查那一层额外要求有没有漏。**

## 人工确认怎么做（建议顺序）

1. **确认主体与业务落点**：公司注册地、实际经营地、用户与门店所在地、服务器与数据存储地。
   通常以实际经营地 / 业务发生地为主，具体口径请咨询法务或当地主管部门。
2. **确认是否包含上海或深圳**：只要有一项业务实际落在其中一市，就建议按对应条例自查。
3. **确认城市对应的规则**：
   - 上海 → `LR-SH-23`（上海市数据条例第二十三条）
   - 深圳 → `LR-SZ-26` / `LR-SZ-29` / `LR-SZ-73` / `LR-SZ-75` / `LR-SZ-79` / `LR-SZ-80`
4. **确认是否还有其他城市**：北京、广东、浙江等地另有地方性数据规则，本插件不覆盖。
5. **确认后再跑本插件**，并把「适用范围需人工确认」这句话一起写进报告结论，
   不要让读者误以为这是全国通用结论。

## 报告里的提示在哪里

- 文本报告**第一行**：`深鲸守护 · 地方数据条例检查（仅上海 / 深圳）· 适用范围需人工确认`
- 文本报告**页脚**：`本插件只覆盖上海、深圳两市条例；是否适用取决于实际运营地，需人工确认。`
- HTML 报告标题和页脚同样带这条声明

## 不适用的典型情况

- 业务只在其他城市，且没有上海/深圳的业务落点
- 纯内部工具、不处理个人信息，也不对外提供数据
- 只做离线计算、不采集也不存储个人数据

以上情况跑出来的命中不应作为整改依据；如果仍有疑虑，请让法务/合规同事确认。
